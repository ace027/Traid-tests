## Key Design Decisions
- Board quick-assess (phase 4, pre-plan) adopted as constraints: an end-to-end server test (fake download client completes -> imported + renamed -> downloadFolderImported history -> episode no longer in wanted/missing); an import failure leaves the source file intact; .ics output validated against RFC 5545 rules (CRLF, 75-octet folding, UID, DTSTAMP, escaping); naming-template preview with live examples; explicit upgrade rules (no downgrade, cutoff respected, proper/repack per setting); extend phase-3 history/blocklist services; agenda view as the calendar default below md; status always shown with icon + text; empty/loading/error states on every new page. Its REJECT red flag only reflected that no phase-4 plans existed yet.
- Config keys (config table): 'mediamanagement' and 'naming' and 'downloadclientconfig'. Media management defaults: autoUnmonitorPreviouslyDownloadedEpisodes false, recycleBin '' (disabled), recycleBinCleanupDays 7, downloadPropersAndRepacks 'preferAndUpgrade' (doNotUpgrade|doNotPrefer), createEmptySeriesFolders false, deleteEmptyFolders false, fileDate 'none', skipFreeSpaceCheckWhenImporting false, minimumFreeSpaceWhenImporting 100 (MB), copyUsingHardlinks true, importExtraFiles false, extraFileExtensions 'srt,nfo', setPermissionsLinux false, chmodFolder '755'. Naming defaults: renameEpisodes true, replaceIllegalCharacters true, colonReplacementFormat 'smart' (delete|dash|spaceDash|spaceDashSpace|smart), multiEpisodeStyle 'prefixedRange' (extend|duplicate|repeat|scene|range|prefixedRange), standardEpisodeFormat '{Series Title} - S{season:00}E{episode:00} - {Episode Title} {Quality Full}', dailyEpisodeFormat '{Series Title} - {Air-Date} - {Episode Title} {Quality Full}', animeEpisodeFormat '{Series Title} - S{season:00}E{episode:00} - {absolute:000} - {Episode Title} {Quality Full}', seriesFolderFormat '{Series TitleYear}', seasonFolderFormat 'Season {season:00}', specialsFolderFormat 'Specials'. Download client config: enableCompletedDownloadHandling true, autoRedownloadFailed true.
- Naming engine (server/src/naming/) supports Sonarr tokens: {Series Title} {Series TitleYear} {Series CleanTitle} {Series TitleThe}, {season:0} {season:00} {episode:0} {episode:00} {absolute:00} {absolute:000}, {Episode Title} {Episode CleanTitle}, {Air-Date} {Air Date}, {Quality Full} {Quality Title} {Quality Proper}, {Release Group}, {Original Title} {Original Filename}; case variants by token casing ({series title} lowercase, {SERIES TITLE} uppercase) and separator variants ({Series.Title}, {Series_Title}); unknown tokens are left as-is and reported by validation; illegal path characters replaced; results trimmed; the default formats round-trip through parseTitle (test).
- Import pipeline (server/src/import/): source = a file or folder (download outputPath or manual path); candidate video files (VIDEO_EXTENSIONS, no samples); each file is mapped to series/episodes preferring the tracked download's history match, else parseTitle + series title mapping; import specifications produce rejections: 'Not a video file', 'Sample', 'Unable to parse file', 'Unknown Series', 'Episode(s) not found', 'Not an upgrade for existing episode file(s)', 'Not enough free space', 'Episode file already imported', 'Locked file, try again later'. Transfer: usenet = move (fs.rename, EXDEV -> copy + size check + unlink); torrent or item.canMoveFiles=false = hardlink when copyUsingHardlinks else copy; destination from the naming engine within series path/season folder; existing destination name collision gets ' (1)' suffix. Upgrade: replaced files go to the recycle bin (recycleBin/{Series Folder}/...) when configured, else are deleted; history episodeFileDeleted (reason 'upgrade') then downloadFolderImported. A failed transfer leaves the source untouched and removes partial destination files.
- Completed download handling runs inside RefreshMonitoredDownloads when enableCompletedDownloadHandling: importPending items are imported (state importing -> imported on success; on rejection the item stays importPending with trackedDownloadStatus warning and the rejection messages); after a successful import the client item is removed when the client's removeCompletedDownloads is on and item.canBeRemoved (deleteData true). Imported state persists via the downloadFolderImported history for that downloadId. Failed download handling: failed items record downloadFailed history once, blocklist the release, remove from client when removeFailedDownloads, and enqueue EpisodeSearch for the episodes when autoRedownloadFailed. The decision engine's queue specification ignores failed and imported items.
- Wanted API: GET /api/v3/wanted/missing and /api/v3/wanted/cutoff (paged; sortKey airDateUtc default descending; monitored=true default; includeSeries). Calendar: GET /api/v3/calendar?start&end&unmonitored=false&includeSeries=true. iCal: GET /feed/v3/calendar/sonarr.ics?pastDays=7&futureDays=28&unmonitored=false&premieresOnly=false&asAllDay=false&tags= (API key via apikey query, already allowed on /feed/*).
- Web: new pages Activity History, Activity Blocklist, Wanted Missing, Wanted Cutoff Unmet, Calendar (month/week/agenda, iCal link modal), expanded Media Management (naming with live preview, folders, importing, file management, recycle bin), Completed/Failed download handling card on Download Clients, Manual Import modal from the queue, Rename preview modal on series detail. Design: existing tokens and components; status icon + text; tables scroll horizontally; calendar agenda default below md.
- Route stubs created by 04-01 so the parallel wave-2 server plans never edit app.ts: routes/wanted.ts, routes/calendar.ts (including the feed), routes/manualimport.ts, routes/rename.ts. Plan 04-02 registers its commands from inside its route plugins (manualimport.ts) and its completed/failed handling inside queue.ts. Domain workflow, spec and architecture proposals skipped (autonomous defaults). No new npm dependencies.
