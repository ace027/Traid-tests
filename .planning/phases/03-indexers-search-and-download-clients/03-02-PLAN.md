Input capped at 20 MB. types.ts: ReleaseInfo {guid, title, size, publishDate (ISO), downloadUrl, infoUrl?, indexerId, indexer, indexerPriority, protocol, seeders?, leechers?, tvdbId?, tvMazeId?, imdbId?, categories: number[], infoHash?, magnetUrl?}; SearchCriteria = {type:'episode', series, seasonNumber, episodeNumbers} | {type:'season', series, seasonNumber} | {type:'daily', series, airDate} | {type:'anime', series, absoluteEpisodeNumbers} where series = {title, tvdbId, tvMazeId, imdbId, cleanTitle}; interface IndexerClient {test(): Promise<void>; fetchRss(): Promise<ReleaseInfo[]>; search(criteria): Promise<ReleaseInfo[]>}; class IndexerError(message, status?). newznab.ts: createNewznabClient(indexerRow, {fetch, now}) for both implementations (torznab sets protocol torrent, reads seeders/peers/infohash/magneturl attrs, minimumSeeders not applied here). URL building: baseUrl + apiPath + '?t=..&apikey=..&cat=..&extended=1&limit=100'; tvsearch with tvdbid when known else q=title (cleaned of punctuation), season/ep per criteria (daily: season=YYYY, ep=MM/DD; season search without ep; anime: t=search q='title absolute' with animeCategories); RSS: t=tvsearch without query params (Sonarr) and categories. 30 s timeout via AbortSignal.timeout; HTTP 401/403 or <error code=100-102> -> IndexerError('Invalid API key'); 429 -> IndexerError with retry hint; size from enclosure length or size attr; publishDate from pubDate (RFC 822) or usenetdate attr; downloadUrl from enclosure url or link. test() requests t=caps and fails if tv-search is unavailable. Never log the apikey (redact in error messages). Tests use a fake fetch with fixture XML strings (newznab feed, torznab feed with seeders/infohash/magnet, error response, caps): URL composition per criteria type, parsing, entity decoding, error mapping, apikey redaction, a 5 MB pathological input parses in < 500 ms.
