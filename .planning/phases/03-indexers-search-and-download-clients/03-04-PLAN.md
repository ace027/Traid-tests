types.ts: RemoteEpisode {release: ReleaseInfo, parsed: ParsedEpisodeInfo, series?: SeriesRow, episodes: EpisodeRow[]}; DownloadDecision {remoteEpisode, rejections: Rejection[], approved: boolean, temporarilyRejected: boolean}; SearchContext {searchCriteria?: SearchCriteria, interactive: boolean, now}. engine.ts: makeDecisions(app, releases, ctx) parses each release title with parseTitle (unparseable -> rejection 'Unable to parse release'), maps to a series (by tvdbId from the release, then tvMazeId, then cleanSeriesTitle against series.clean_title and title without year; when searchCriteria is given, the criteria series is used if titles match) -> 'Unknown Series', maps episodes (standard season/episodes; daily by air_date; anime by absolute number then season/episode; full season -> all episodes of the season except specials) -> 'Unable to identify correct episode(s) using release name and scene mappings' when none; then runs specifications in order and collects every rejection. specifications.ts (each a pure function returning Rejection | null; reasons use Sonarr wording): (1) not requested when searchCriteria given and episodes are outside it -> 'Episode wasn't requested' (permanent); (2) quality allowed -> 'Quality {name} is not wanted in profile'; (3) monitored: series not monitored -> 'Series is not monitored', episode(s) not monitored -> 'Episode is not monitored' (both skipped for interactive searches of explicitly requested episodes); (4) full season pack requires every non-special episode of the season monitored and aired -> 'Full season pack: not all episodes are monitored/aired'; (5) size: per-episode size limits from quality_definitions (MB/min * runtime (series runtime, default 45, 30 for anime when unknown) * episode count; season pack uses sum of runtimes) -> '{size} is smaller than minimum allowed {min}' / '{size} is larger than maximum allowed {max}'; size 0 or unknown is accepted; (6) upgrade vs existing file: when any episode has a file, compare via quality weight then revision version: not an upgrade -> 'Existing file on disk is of equal or higher preference: {quality}'; existing file meets cutoff (weight >= cutoff weight) and new quality is not a revision upgrade of the same quality -> 'Existing file meets cutoff: {quality}'; upgrades disabled in profile -> 'Existing file and the Quality profile does not allow upgrades'; (7) queue: release for episodes already in the queue with equal or better quality -> 'Release in queue already meets cutoff: {quality}' or 'Release in queue is of equal or higher preference: {quality}' (temporary); (8) blocklisted -> 'Release is blocklisted' (isBlocklisted); (9) torrent minimum seeders from indexer settings -> 'Not enough seeders: {n}. Minimum seeders: {m}'; (10) already grabbed recently (history grabbed for same episodes with equal/better quality within 12 h) -> 'Has been grabbed recently' (temporary, Sonarr's RecentlyGrabbed for RSS only). prioritize.ts: sortDecisions per CONTEXT (approved first; quality weight desc; revision desc; indexer priority asc; usenet before torrent; seeders desc; publish date desc). engine.test.ts: table-driven tests for every specification and the ordering using fixture series/episodes/files rows inserted through createTestApp + fake metadata, plus season pack and daily and anime mapping.

Commands: EpisodeSearch {episodeIds}, SeasonSearch {seriesId, seasonNumber} (season pack criteria first, then individual missing monitored episodes when no pack is approved), SeriesSearch {seriesId} (every monitored season), MissingEpisodeSearch {} (monitored, aired, no file; batches of 50), CutoffUnmetEpisodeSearch {} (monitored with file below cutoff); each updates its command message 'Found N releases, grabbed M'. rss.ts: RssSync command: fetchRss from all rss indexers, makeDecisions without criteria, grab approved (one per episode set), message 'RSS Sync Completed.
