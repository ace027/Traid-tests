## Key Design Decisions
- Board quick-assess (phase 3, pre-plan, not evidence-based) recommendations adopted: extend (not rebuild) the phase 2 parser for releases; minimal history (grabbed events) and blocklist tables + read/delete API in this phase, management UI stays in phase 4; a small scheduler service now, reused by phase 5's task page; explicit non-goals below; RSS sync success criterion with a fake feed that grabs an approved release and skips a duplicate; UI rejections and progress shown with text (not colour only), responsive tables, empty/loading/error states.
- Non-goals for this phase (deferred, recorded): delay profiles, release profiles (must/must-not contain), custom formats, enforcing torrent seed ratio/time (stored only), indexer search for specials by name, push releases API, proxy settings.
- Migration 0004_indexers_downloads.sql: indexers, download_clients, history, blocklist, scheduled_tasks tables (columns in plan 03-01). Credentials (indexer apiKey, client password/apiKey) are stored in SQLite and returned masked as '********'; a PUT carrying '********' keeps the stored value.
- Resource shapes live in shared/src/indexers.ts (IndexerResource, DownloadClientResource, ReleaseResource, QueueResource, HistoryResource, BlocklistResource, Rejection). Indexer and client settings are a typed `settings` object (not Sonarr's fields array).
- Scheduler: server/src/services/scheduler.ts; scheduled_tasks rows (name, command_name, interval_minutes, last_execution, next_execution); a 30 s tick enqueues due commands with trigger 'scheduled' (skips one already queued/running); default tasks: RssSync every 15 min, RefreshMonitoredDownloads every 1 min, RefreshSeries every 12 h, Housekeeping every 24 h. GET /api/v3/system/task lists them; disabled in tests unless started explicitly.
- Indexer protocol: Newznab/Torznab XML over HTTP via injectable fetch (no dependencies); a small tolerant XML item reader (no regex backtracking hazards) in server/src/indexers/xml.ts; caps test via t=caps; search t=tvsearch with tvdbid/season/ep (daily season=YYYY ep=MM/DD; anime q=title+absolute), t=search with q fallback when no tvdbId; RSS = t=search without q, cat filter, limit 100; 30 s timeout; per-indexer failure backoff in memory (5, 15, 30, 60 min ... cap 24 h) reset on success.
- Download clients implement DownloadClient {test(), addRelease(release, torrentFile?), getItems(), removeItem(downloadId, deleteData)} with injectable fetch: SABnzbd (api mode=addurl/queue/history/delete, apikey), NZBGet (JSON-RPC append with URL content, listgroups, history, editqueue GroupFinalDelete/HistoryFinalDelete, basic auth), qBittorrent (WebUI API v2 cookie login, torrents/add, torrents/info?category, torrents/delete), Transmission (RPC with X-Transmission-Session-Id 409 handshake, torrent-add filename/metainfo, torrent-get, torrent-remove, labels [category]). Torrent downloadId = lowercase info hash: from magnet btih, else fetched .torrent file hashed by a minimal bencode reader (sha1 of the raw info dict) and uploaded as the file.
- Decision engine in server/src/decision/: specifications run per parsed release and produce Rejection {reason, type permanent|temporary}; Sonarr wording for reasons (see plan 03-04). Prioritization for automatic grabs: quality weight desc, revision version desc, indexer priority asc, protocol usenet before torrent, seeders desc (torrent), size asc for equal quality? no: size desc closer to preferred size is ignored; publish date newest first. Only approved decisions are grabbed automatically; interactive grab may grab a rejected release explicitly.
- Grab: download client chosen by protocol, enabled, lowest priority value, honoring tags (a client with tags is only used for series sharing a tag; otherwise untagged clients). History row event_type 'grabbed' with download_id; queue tracking matches download items to history by download_id. Queue ids are stable integers assigned in memory per (clientId, downloadId). Queue polling via the RefreshMonitoredDownloads command (every minute) and on GET /api/v3/queue when the cache is older than 5 s; changes publish 'queue' events.
- UI follows the existing design system and settings patterns: Indexers and Download Clients settings pages (cards, add/edit modal, Test button, tags), Activity > Queue page, Interactive Search modal on series detail (episode and season level), automatic search buttons. Release rejections shown as an icon with an accessible list of text reasons; queue progress bar has role=progressbar with aria-valuenow and visible percentage text; tables scroll horizontally on small screens.
- Domain workflow, spec and architecture proposals: skipped (autonomous defaults). No new npm dependencies.

## Plan Structure
- **Plan 03-01 (Wave 1)**: Phase 3 foundations: schema, shared types, scheduler, history and blocklist -- Add the indexer/download client/history/blocklist/scheduled task schema, the shared resource types for the whole phase, the scheduler service, history and blocklist services with their read/delete API, and stub route plugins for indexers and download clients.
- **Plan 03-02 (Wave 2)**: Newznab and Torznab indexers -- Implement Newznab and Torznab indexer clients (caps test, tvsearch, RSS) with a dependency-free XML reader, failure backoff, and the /api/v3/indexer resource (CRUD, schema, test).
- **Plan 03-03 (Wave 2)**: Download clients and queue tracking -- Implement SABnzbd, NZBGet, qBittorrent and Transmission clients, the /api/v3/downloadclient resource, and tracked downloads with the /api/v3/queue API and the RefreshMonitoredDownloads command.
- **Plan 03-04 (Wave 3)**: Decision engine, search, RSS sync and grabbing -- Turn releases into download decisions with Sonarr's rejection rules and prioritization, implement automatic searches, interactive release search and grab, and scheduled RSS sync that grabs approved releases.
- **Plan 03-05 (Wave 2)**: Indexer, download client, queue and interactive search UI -- Build Settings > Indexers and Download Clients, the Activity > Queue page, the Interactive Search modal and automatic search actions on the series detail page, against the shared phase 3 resource types.
