## Deferred (Medium Confidence)
- `src/client/net.ts` [major, 70%]: `rawSend` silently drops messages when the socket is not open. `onclose` with code 4000 returns without scheduling a reconnect and without setting any error or message, so the "Reconnecting to server..." banner stays up forever. There is also no user feedback for sends dropped during a disconnect.
- `src/client/net.ts` [minor, 55%]: Rejoin-failure handling clears `state` and `lobby` only while `rejoinPending` is true. `rejoinPending` is set only if the stored session exists. If the server's reply to rejoin is not `joined` or `error` (for example a `lobby` or `state` message), the flag stays set. Any later unrelated `error`, such as a validation error from a bad action, then wipes the session and the game state. `main.ts` then calls `location.reload()` because `state` is null.
- `src/client/main.ts` [minor, 65%]: `showGame` calls `store.subscribe` for the banner and never unsubscribes. The module-level `inGame` flag duplicates what the store already tracks (`state` being non-null). The `!s.state && inGame` branch resets the app with `location.reload()`.
- `src/client/ui/hud.ts, src/client/ui/battle.ts` [minor, 55%]: The `as never` casts bypass type checking on the `stepsAvailable`, `computeScore` and `renderLog` calls. In `battle.ts`, `m?.stats as Stats` is spread when `getMonster` returns undefined, so stats come out as undefined and the fallback name is just "Monster".
- `src/client/ui/hud.ts, src/client/ui/gameover.ts` [minor, 75%]: `state as never` is passed to the engine functions `stepsAvailable` and `computeScore` in three places. `PublicGameState` apparently doesn't match the engine's `GameState` type, and `as never` switches off type checking for the whole argument.
- `src/client/ui/battle.ts` [minor, 60%]: `{ ...(m?.stats as Stats), hp }` casts away the possibility that the monster is undefined. If the monster lookup fails, the spread is of `undefined`, which gives an object with only `hp` and then crashes or renders NaN stats in `combatant`.
- `src/client/ui/hud.ts; src/client/ui/hud.css; src/client/styles.css` [minor, 70%]: `render()` runs on every store update. It rebuilds the top bar, scoreboard, context panel (including the shop, battle and inventory DOM) and the log with `textContent = ''` followed by append. It never checks whether `state` or `lastEvents` changed.
- `src/client/styles.css` [minor, 60%]: Buttons and inputs have only `padding: 8px 10px` and no minimum height. The shop and inventory row buttons inside `.hud li`, which has `padding: 3px 0`, are likely under 44px tall. The canvas also registers only `click` and `mousemove` (board.ts 456-457), with no touch or pointer handling or `touch-action`.
- `src/client/net.ts` [minor, 70%]: `rawSend` silently drops messages when the socket is not open. Malformed JSON from the server is also silently ignored, and `as ServerMessage` is an unchecked cast.
- `src/client/render/board.ts` [minor, 60%]: `mountBoard` returns silently when `getContext('2d')` is null. The canvas stays blank with no message.
- `src/client/ui/lobby.ts` [advisory, 60%]: `entry.hidden` and `entry.style.display` are both set, so there are two mechanisms for one state. The `dataset.fromStore` flag used to track error ownership is awkward.
- `src/client/styles.css, src/client/ui/hud.css` [minor, 70%]: There is only one dark palette and no light, dark or system theme toggle. There is no `prefers-color-scheme` or `prefers-reduced-motion` handling, even though animate.ts drives canvas animation. Sizes, radii and spacings are hard-coded (8px, 16px, 260px, 320px) instead of tokens, and `#fff` and `#1a120a` are hard-coded colours.
- `src/client/ui/lobby.ts, src/client/main.ts` [minor, 65%]: The "Reconnecting to server..." banner is built twice, once in the lobby and once in main.ts. Both are `position: fixed` with `z-index: 100`, so two banners can stack when the lobby and the HUD are both mounted. The banner shows no reconnect state or outcome, such as a failed or terminal state, and has no retry control.
- `src/client/ui/battle.ts` [minor, 65%]: The HP bar is a plain `div` fill with a text label and no `role="progressbar"` or aria-value attributes. The fill is `--ok` green regardless of HP level. The portrait is a hashed-colour box with no accessible name.
- `src/client/styles.css` [minor, 60%]: `button:disabled` uses `opacity: 0.5` on the accent background with dark text, and `.muted`/`--muted` (#a39580) text on `--panel-2` is borderline. The "danger" banner uses #fff on #c4503f, about 4.1:1, which is below 4.5:1 for small text. Disabled buttons have no explanation of why they are disabled, for example the lobby Start button needing 2-4 seats, or unaffordable shop items.
- `src/client/ui/lobby.ts` [advisory, 55%]: The entry form is toggled between `display: contents` and `none` with inline styles instead of the `hidden` attribute or a class. The room-code display has no copy affordance, and the code is not announced.
- `src/client/ui/gameover.ts` [major, 70%]: The game-over view has no "back to lobby" or "new game" action. `rr.code` and `rr.token` stay in sessionStorage, and `main.ts` only reloads when `state` becomes null. A reload after game-over rejoins the finished game.
- `src/client/ui/log.ts` [minor, 60%]: `describeEvent` has no cases for `town-claim`, `town-toll`, `leave-shop`, `move`, `auto-end-turn` or any PvP result. These events fall through to `null`, and no player-disconnect event is shown either.
- `src/client/ui/battle.ts` [minor, 55%]: A "Item: X" button is added for every inventory entry, so duplicate consumables produce duplicate buttons. The defender in PvP only sees "Waiting for X to act". The portrait is a placeholder coloured box rather than `art.ts`.
