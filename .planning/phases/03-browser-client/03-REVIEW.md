## Suggestions (Not Required)
- F-002 `src/client/ui/hud.ts`: `state as never` is used to call `stepsAvailable` and `computeScore`. This bypasses the type system. (fix: Make the engine functions accept the structural subset they use, such as `Pick<GameState, ...>`. Alternatively, add a single typed adapter. Remove the `never` casts.)
- F-003 `src/client/ui/battle.ts`: `portrait()` carries a stale development comment ("art.ts is created in parallel; draw a coloured box instead"). art.ts now exists and exports `drawMonster` and `drawToken`, but the combat screen still shows a hashed-hue div. Line 58 also casts `m?.stats as Stats`. When `getMonster` returns undefined this spreads `undefined` and yields a `Stats` object with only `hp`. (fix: Render the portrait with a canvas that calls `drawMonster` or `drawToken`. Delete the stale comment. Replace the cast with a guard: if `m` is undefined, use a fallback `Stats` or skip the monster combatant.)
- F-004 `src/client/ui/gameover.ts, src/client/ui/hud.ts`: `state as never` is passed to the engine functions `computeScore` and `stepsAvailable`. `PublicGameState` does not match the engine's `GameState`, and the cast silences the compiler. (fix: Give the engine functions a narrower structural parameter type, such as `Pick<GameState, ...>`, or add one typed adapter, `toEngineState(PublicGameState)`, instead of casting in three places.)
- F-005 `src/client/styles.css`: The `.hud` and `.hud > *` rules are declared twice. The first pair is dead code. `.hud` is also declared in `hud.css` (unverified, not read in full). (fix: Delete lines 33-34 and keep the HUD layout in one file.)
- F-006 `src/client/ui/shop.ts`: Every Buy and Sell button just says "Buy" or "Sell". Screen readers hear a list of identical names. Disabled Buy buttons give no reason. The same applies to Equip/Use in `inventory.ts` (lines 24-28) and to Upgrade/Capture in `town.ts`, where there is no explanation of why Upgrade is disabled (max level or too little gold). (fix: Set `aria-label="Buy ${item.name}"` on each button. Add visible or `title` text for disabled reasons, such as "Max level" or "Need 80g".)
- F-008 `src/client/ui/town.ts`: The upgrade cost (`80 * level`), the capture cost (`150 * level`) and the max level (3) are hardcoded. The engine defines them as UPGRADE_COST_PER_LEVEL, CAPTURE_COST_PER_LEVEL and MAX_TOWN_LEVEL in src/engine/movement.ts. The values match today. (fix: Import the constants from the engine. Export them from src/engine/index.ts if they are not already exported.)
- F-009 `src/client/ui/lobby.ts`: The start button's enable rule hardcodes `seats.length < 2 || > 4`. The server uses MIN_PLAYERS and MAX_PLAYERS from the engine. (fix: Import MIN_PLAYERS and MAX_PLAYERS from '../../engine'.)
- F-011 `src/client/ui/town.ts`: The costs `80 * level` and `150 * level` and the cap `>= 3` are hard-coded. The engine defines `UPGRADE_COST_PER_LEVEL`, `CAPTURE_COST_PER_LEVEL` and `MAX_TOWN_LEVEL` in `src/engine/movement.ts`. (fix: Import the constants from the engine and use them. Also show "Max level" instead of a disabled "Upgrade" button at the cap.)
- F-013 `src/client/main.ts`: The in-game banner is hidden only when `connection === 'open'`. When the connection is replaced, it still shows "Reconnecting to server..." beneath the replaced notice. The client is not reconnecting in that case, so the text is contradictory. The `store.subscribe` call inside `showGame` also has no unsubscribe. (fix: Hide the banner when `isReplaced(s)`, or derive the banner text from the connection state. Return an unsubscribe from `showGame`.)
- F-018 `tests/client/hud.test.ts`: F-017 is resolved, so this is not a defect. The `hud inventory gate` suite covers every case the finding listed. A waiting player gets no toggle or panel even after clicking. The toggle is hidden in battle, choose-path and game-over. ## Deferred (Medium Confidence)
- `src/client/main.ts` [major, 75%]: `showGame` adds a `store.subscribe` for the banner and never unsubscribes. The subscription is also created again on each `showGame` call. When state becomes null mid-game, the code recovers with `location.reload()`. That drops the connection, and any lobby UI state is lost along with it. `mountBoard` and `mountHud` return no unmount (hud.ts:186 discards the unsubscribe from `store.subscribe(render)`). The HUD toast timer and the path handler are never torn down either.
- `src/client/ui/battle.ts` [minor, 60%]: `{ ...(m?.stats as Stats), hp }` is a cast over a possibly undefined monster. An unknown monster id gives a Stats object with only `hp`, so `maxHp` is undefined.
- `src/client/ui/battle.ts` [minor, 75%]: `portrait()` draws a hue-coloured box. A comment says "art.ts is created in parallel". The task requires original placeholder art, and `art.ts` exists, but the battle screen does not use it.
- `src/client/styles.css` [minor, 70%]: Buttons have padding of 8px 10px and no `min-height`. They render at about 36px tall, below the 44px touch target. This includes the HUD action buttons (Attack, Go to tile, Roll) and the shop buy buttons on the mobile breakpoint (hud.css:24). Inputs and selects have no `font-size` of at least 16px, so iOS zooms the page on focus in the lobby.
- `src/client/ui/hud.css` [minor, 50%]: On desktop, `.hud-context` has `max-height: 70vh` and `overflow: auto`, while the log panel in row 3 and the inventory in column 3 row 3 occupy fixed grid cells. At short viewport heights (landscape phones wider than 800px), the side panels, context panel and inventory overlap or cover the board. No height-based media query exists.
- `src/client/ui/hud.ts` [minor, 60%]: `patch()` replaces the DOM through `innerHTML` comparison. Focus is restored only when the label and index are unchanged. A focused button that vanishes or changes its label (Roll → End Turn, Buy → disabled) drops focus to `body`. Buttons that become disabled also lose focus.
- `src/client/net.ts` [minor, 65%]: Incoming server frames are cast to `ServerMessage` with `JSON.parse(...) as ServerMessage` and no shape check. A frame that is not an object, or has an unknown `t`, reaches `reduceServerMessage`. That function has no default case and returns `undefined`, and `msg.t` throws a TypeError for a `null` payload.
- `src/client/main.ts` [minor, 75%]: `showGame` calls `store.subscribe` for the banner and discards the unsubscribe function. The game-to-lobby transition is `location.reload()`. The `app!` non-null assertions repeat even though `app` is checked at module level.
- `tests/e2e/smoke.spec.ts` [major, 65%]: Both e2e tests duplicate about 30 lines of setup. `playTurn` only advances through movement, Attack, Leave, Go to, and End Turn. It never opens the shop, inventory, town upgrade, capture or PvP views. Its loops can pass on swallowed errors: `.catch(() => {})` ignores click failures, and "Waiting for" returns early.
- `tests/client` [minor, 50%]: No test file exists for the `renderBattle` null-monster path (`getMonster` returning undefined, battle.ts line 58) or for `renderGameOver`. The listed tests are board, hud, lobby and store only.
- `src/client/ui/hud.ts` [major, 65%]: The top HUD bar (`hud-top`) is `role="status"` with `aria-live="polite"`. `patch()` rebuilds it whenever gold, HP, day or turn changes, so a screen reader re-announces the whole bar each time. The error toast is `role="alert"` and also lives in the HUD.
- `src/client/styles.css` [advisory, 60%]: There is a single fixed dark palette. The design-system default of a light/dark/system toggle is missing. There is no `prefers-color-scheme`, no `prefers-reduced-motion` handling, and no spacing or typography tokens (hard-coded 8/12/16px and font sizes). Colours in `button` (`#1a120a`) and `.banner` (`#fff`) are hard-coded, not tokens.
- `src/client/ui/battle.ts` [minor, 55%]: Each consumable in the inventory gets a separate "Item: X" button. Duplicates produce identical buttons with no count. The Skill button never shows disabled or cooldown states, even if the skill is unusable. The `round-events` list has `role="log"` and `aria-live` while being fully re-rendered each time, which causes repeated announcements.
- `src/client/ui/hud.ts, src/client/styles.css` [minor, 60%]: The `.toast` and `.notice` text uses `--danger` (#c4503f) on `--panel-2` (#2d2520), which is about 3.4:1 contrast. That is below 4.5:1 for normal text. `.muted` (#a39580) on `--panel` is about 5:1 and passes.
- `src/client/ui/hud.ts` [minor, 50%]: There is no visible hint for the current phase beyond the button label ("Roll", "End Turn"). The `waiting` message does not say why the player is waiting. After a defeat, the notice is shown, but if the player is not current they see both the notice and "Waiting for X".
- `src/client/ui/hud.css, src/client/styles.css` [major, 50%]: On narrow viewports, `.hud` is `position: fixed` with a scrolling grid on top of the board canvas. Panels cover the page and only a 45vh spacer remains for the board. At 800px and above the fixed 260px/320px side columns leave little board width on a 1024px screen. The `.hud-context` panel has `max-height: 70vh` and the inventory (row 3, column 3) may overlap the log or the End Turn button (`.hud > button` is at column 2, row 3).
- `src/client/render/board.ts` [minor, 50%]: The board is a `canvas` with `role="img"`. Its tile choices are reachable by mouse click only, via `setPathHandler`. A keyboard-only fallback exists through the HUD path buttons, which is good, but the canvas itself has no `tabindex`.
- `src/client/ui/gameover.ts` [minor, 70%]: The game-over screen only shows a ranking inside the side context panel. It has no "Play again" or "Back to lobby" action and no focus move to the result.
- `src/client/net.ts, src/server/server.ts (consumer/provider)` [advisory, 50%]: The session token is kept in sessionStorage and sent over `ws:` when the page is served over http. The server issues UUID tokens, so they are not guessable. There is no origin check or TLS requirement in the dev setup, and none was found in the files reviewed.
- `src/client/main.ts, src/client/ui/gameover.ts` [major, 70%]: The game-over screen shows only the winner banner and ranking. It has no "Leave" or "New game" control, and nothing calls `clearSession()`. The `rr.code` and `rr.token` values stay in sessionStorage. A reload sends `rejoin`, and the player lands back on the finished game.
- `src/client/net.ts` [minor, 60%]: `rawSend` silently discards messages when the socket is not open. Create, Join, Roll and every other action are dropped with no error or queueing.
- `src/client/ui/hud.ts, src/client/ui/battle.ts` [minor, 60%]: There is no PvP-specific view, which the Phase 3 goal calls for ("town and PvP views"). A player-vs-player battle uses the monster layout, with a hashed-colour box as the portrait instead of art. The battle UI never says it is a duel. `battle.ts` still carries a stale comment that art.ts is "created in parallel", and it does not use `render/art.ts`.
- `src/client/ui/log.ts` [minor, 55%]: Event text is deduplicated against `state.log` by exact string match. The engine log says "X challenges Y!" while `describeEvent` produces "X attacks Y". Several other events also have different wording. The events `town-claim`, `buy`, `sell` and `town-toll` return null. Events whose wording differs from the engine log are shown twice.
- `src/client/net.ts` [minor, 60%]: F-001 is only partly fixed. The message is still dropped when the socket is not OPEN. It is now reported, via `Not connected` in the toast and a `false` return, but not queued. The HUD `send` type is `(m) => void`, and `act` ignores the result. The toast for 'Not connected' is also overwritten by `store.set({ error })` calls.
- `src/client/main.ts` [minor, 55%]: Nothing in this file or in net.ts lets the player leave the game. After `game-over`, `rr.code` and `rr.token` stay in sessionStorage, and `clearSession` is only called on a rejected rejoin. A reload re-enters the finished game, and the only way back to the lobby is a rejected rejoin or closing the tab. I did not read gameover.ts, so a "play again" button may exist there.
- `src/client/net.ts (with src/client/ui/hud.ts)` [minor, 70%]: The terminal "replaced" state is still encoded as a magic string in the general-purpose `store.error` field. `isReplaced` compares `error` to `REPLACED_MESSAGE`. `hud.ts` imports `net.ts` just to special-case that string. The lobby (`lobby.ts:131`) prints `s.error` as-is, so it also shows the sentinel text. Any other writer of `error` can still clear the state: a reducer case (`store.ts:58-62` set `error: null`) or a `store.set({error})`. The current fixes (HUD skip, `rawSend` guard) guard only two known writers.
- `tests/client/hud.test.ts` [advisory, 50%]: The "never expires" test never mounts the HUD, so it does not exercise `hud.ts`. It only asserts that the store keeps the value after a timer advance.
