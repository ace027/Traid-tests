## Key Design Decisions
- Metadata provider: TVmaze (https://api.tvmaze.com), behind a MetadataProvider interface {search(term), getSeries(tvmazeId)}; buildApp accepts an optional metadataProvider so tests use a FakeMetadataProvider (server/src/test/fakeMetadata.ts) and never hit the network. Lookup terms: plain text -> /search/shows?q=; 'tvdb:N' -> /lookup/shows?thetvdb=N; 'imdb:ttN' -> /lookup/shows?imdb=; 'tvmaze:N' -> /shows/N. Series detail -> /shows/N?embed[]=episodes&embed[]=seasons (specials via /shows/N/episodes?specials=1). Client: 10 s timeout (AbortSignal.timeout), retry on 429/5xx up to 3 times honoring Retry-After (default 2 s), token bucket 20 requests / 10 s, in-memory search cache 10 min. TVmaze HTML summaries are stripped to plain text server-side. Posters and fanart use TVmaze remote image URLs (no local media cover cache this phase).
- Storage (migration 0003_series.sql): series (unique tvmaze_id, unique tvdb_id when not null, unique path, unique title_slug, quality_profile_id FK -> quality_profiles ON DELETE RESTRICT, add_options JSON nullable, tags JSON, genres JSON, images JSON, ratings JSON); seasons (series_id FK CASCADE, season_number, monitored, UNIQUE(series_id, season_number)); episodes (series_id FK CASCADE, tvmaze_id, season_number, episode_number, absolute_episode_number, title, overview, air_date, air_date_utc, runtime, monitored, episode_file_id FK -> episode_files ON DELETE SET NULL, UNIQUE(series_id, season_number, episode_number), INDEX(series_id, season_number)); episode_files (series_id FK CASCADE, season_number, relative_path, path UNIQUE, size, date_added, quality JSON {quality:{id,name,source,resolution}, revision:{version, real, isRepack}}, release_group, INDEX(series_id)).
- Monitoring: pure function monitorEpisodes(option, episodes, now) in shared/src/monitoring.ts for options all|future|missing|existing|pilot|firstSeason|lastSeason|none (specials, season 0, are never monitored by these options; 'existing' monitors episodes with files; 'missing' monitors episodes without files). At add the option is applied without file knowledge and stored in series.add_options; the first RescanSeries re-applies it with file knowledge and then clears add_options (Sonarr behavior).
- Series folder name: '{Title} ({Year})' with characters <>:"/\|?* removed and trailing dots/spaces trimmed; path = rootFolderPath + folder unless an explicit path is given (Library Import). Root folder must exist in root_folders; an explicit path must be inside a configured root folder (realpath).
- Deleting a series never removes files unless deleteFiles=true; with deleteFiles the folder is removed only if its realpath is inside a configured root folder. Deleting a quality profile used by a series returns 400. tag/detail fills seriesIds.
- Refresh and disk scan run as commands (RefreshSeries {seriesId?}, RescanSeries {seriesId?}) through app.commands, idempotent, publishing 'series'/'episode'/'episodefile' events. Refresh upserts episodes by (season, episode), keeps monitored flags and file links, monitors new episodes when series.monitored and the season is monitored (and monitorNewItems='all'), and deletes episodes that disappeared only if they have no file.
- Disk scan: realpath of series.path must be inside a configured root folder; walk with max depth 4 and max 20000 entries, do not follow symlinks that resolve outside the series folder, video extensions .mkv .mp4 .avi .m4v .wmv .ts .mov .webm .mpg .mpeg .m2ts, skip names containing 'sample' (case-insensitive) and files under 'extras'/'featurettes' folders; parse with the parser, match by season/episode (daily by air date, anime by absolute number), insert/update episode_files, link episodes, unlink and delete episode_files rows whose file is gone; unparseable files are reported in the command message, never silently dropped.
- Parser lives in server/src/parser/ (pure, no I/O) and will be reused by phase 3 for release titles: parseTitle(title) -> ParsedEpisodeInfo | null and parseQuality(name) -> QualityModel, following Sonarr's rules (SxxEyy, multi-episode SxxEyyEzz / Eyy-Ezz, 1x01, daily YYYY.MM.DD / YYYY-MM-DD, anime '[Group] Title - 01', full season packs, PROPER/REPACK/v2 revisions, resolution 480/576/720/1080/2160, sources HDTV/WEB-DL/WEBRip/BluRay/Remux/DVD/SDTV). All regexes must be linear-time (no nested quantifiers) to avoid ReDoS.
- Series list returns per-series statistics via grouped queries (no N+1): seasonCount, episodeCount (monitored and (aired or has file)), episodeFileCount, totalEpisodeCount, sizeOnDisk, percentOfEpisodes, previousAiring, nextAiring; per-season statistics likewise.
- Web: poster grid uses aspect-ratio 2/3 boxes with loading=lazy and decoding=async; series index view mode, sort and filter persist in localStorage; the lookup input is debounced 300 ms; TVmaze text is rendered as plain text (never dangerouslySetInnerHTML).
- Board quick-assess (phase 2): no evidence-based red flags (no phase-2 code existed yet). Its recommendations are adopted above: unique tvmaze id, FKs with cascade, indexes, commands for refresh/scan, timeout/retry/cache/rate limit for TVmaze, path confinement and caps for the scan, non-destructive delete by default, parser test table, aggregate counts, lazy posters. CI workflow and benchmarks are deferred (out of phase scope). Domain workflow, spec and architecture proposals: skipped (autonomous defaults).

## Plan Structure
- **Plan 02-01 (Wave 1)**: Series data model, TVmaze provider and series API -- Add the series/season/episode/episode_file schema, the shared series types and monitoring logic, a rate-limited TVmaze metadata provider with a test fake, and the /api/v3/series resource (lookup, list with statistics, get, add, edit, delete).
- **Plan 02-02 (Wave 1)**: Filename and release title parser -- Implement a pure, linear-time parser that extracts series title, season/episode numbers (standard, multi-episode, daily, anime absolute, season packs), quality (source, resolution, revision) and release group from file names and release titles, with a large test table.
- **Plan 02-03 (Wave 2)**: Episodes API, refresh and disk scan commands, library import -- Expose episodes and episode files through /api/v3, implement the RefreshSeries and RescanSeries commands (metadata refresh and disk scan linking files to episodes), and support Library Import by reporting unmapped folders in root folders.
- **Plan 02-04 (Wave 2)**: Series UI: add, library import, index and detail -- Build the modern series experience: Add New (search + add modal), Library Import, the Series index (poster, overview and table views with sort, filter and search) and the Series detail page (seasons, episodes, monitoring, edit, delete, refresh and scan).
