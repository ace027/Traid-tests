## Deferred (Medium Confidence)
- `server/src/services/series.ts (data from server/src/services/metadata/tvmaze.ts 135-158)` [major, 60%]: `addSeries` bulk-inserts all provider episodes with no dedupe on (season, episode). The table has `UNIQUE (series_id, season_number, episode_number)`. `refreshSeries` dedupes with `seen`, but `addSeries` does not. `mapEpisodes` also passes TVmaze rows through unchanged, so duplicate or renumbered numbers in provider data reach the insert.
- `server/src/services/series.ts` [major, 55%]: `deleteSeries` runs the irreversible `fs.rmSync` first and the DB delete second. An `rmSync` error (EACCES, EBUSY) is not mapped and surfaces as a 500. The folder can then be partially deleted while the series row remains. `fs.existsSync(row.path)` followed by `realpathSync` is also a race: it throws if the path disappears in between. If `series.path` is a symlink, `rmSync(real)` removes the symlink's target tree. That target is still inside a root folder, but it may be another series' folder.
- `server/src/services/diskScan.ts` [minor, 50%]: `existingFiles` is read before the async walk and per-file `stat`, and `episodes` is read after the walk. Nothing serializes scans against refresh or other scans of the same series. A concurrent `RefreshSeries` can delete or renumber episodes between the snapshot and the transaction. A concurrent scan can also work from a stale `existingFiles`.
- `server/src/services/diskScan.ts` [minor, 55%]: `addOptions.monitor` is applied inside the first scan that finds the series folder, overwriting all episode and season `monitored` flags computed by `monitorEpisodes`. Any monitoring toggle the user made between add and the first scan is silently overwritten. Meanwhile, if the scan returns early (folder missing, lines 176-181) or throws, `addOptions` stays set and is re-applied on a later scan, again clobbering manual changes.
- `server/src/routes/episode.ts and server/src/services/episodes.ts` [minor, 70%]: The `episode` "updated" event has inconsistent payload shapes. `PUT /episode/:id` publishes the full API episode object. `PUT /episode/monitor` publishes `{episodeIds, seriesIds, monitored}`. `deleteEpisodeFile` and `scanSeries` publish `{episodeIds, seriesId}` or `{seriesId}`. The PUT handler also uses `as unknown as Record<string, unknown>` to get past the type.
- `server/src/services/diskScan.ts` [minor, 60%]: `parseFile` returns a union of `ParsedEpisodeInfo` and an ad-hoc `{ fallback: ... }` object. Callers must discriminate with `'fallback' in x`. The folder-name and episode-number regexes are also inline and unnamed.
- `web/src/pages/series/SeasonSection.tsx` [minor, 60%]: The per-episode monitor Switch is shrunk with `className="scale-90"`. The rows also have no minimum height or padding around the control.
- `web/src/pages/series/SeriesDetail.tsx` [minor, 55%]: `toggleSeason` builds the whole `seasons` array from the `series` prop and sends it. Only the season being toggled is disabled while a request is pending. `seasonToggleDisabled` is shared, so every season switch is disabled while any one is pending, but the prop lags the server state until the refetch lands.
- `web/src/pages/series/SeasonSection.tsx` [minor, 50%]: The `<section>` has `aria-label={name}`, and the h3 inside it repeats the same name. This creates a duplicate "Season N" region landmark for every season. The collapsed body uses `hidden`, but the body is also unmounted while closed (`{open && ...}`). `aria-controls` therefore points at a div that exists but is empty.
- `web/src/pages/series/SeriesPoster.tsx` [minor, 60%]: The card link has `aria-label={series.title}`. This replaces the link's accessible name, so the network and status badges and the progress bar are not announced as part of the link. The monitored indicator is a `<span title>` that has only an `aria-hidden` icon. Screen readers get no "Monitored" state. The title is also shown twice visually: once in the hover overlay and once below the poster.
- `web/src/pages/series/SeriesDetail.tsx` [advisory, 50%]: The not-found view renders an `sr-only` `<h1>` and an EmptyState with the same title "Series not found". The screen reader user hears the message twice.
- `server/src/services/series.ts` [major, 60%]: `addSeries` inserts `eps` into `episodes` without removing duplicate (seasonNumber, episodeNumber) pairs. The table has `UNIQUE (series_id, season_number, episode_number)`. `refreshSeries` guards against this with a `seen` set, but `addSeries` does not.
- `server/src/services/series.ts (186-189), server/src/app.ts (140-143)` [minor, 75%]: `mapMetadataError` throws an Error with `statusCode: 503`. The global error handler replaces every status >= 500 with the message "Internal Server Error", and it also logs these as server errors.
- `web/src/pages/series/SeriesIndex.tsx` [minor, 60%]: `loadPrefs` validates stored values with `in` checks, such as `parsed.view in { posters: 1, ... }`. The `in` operator also matches inherited keys, so `"toString"` or `"constructor"` passes validation.
- `web/src/pages/series/SeriesIndex.tsx` [minor, 65%]: `sortValue` returns the sentinel string `'9999'` for series with no next airing, and `sortSeries` compares it with `localeCompare` against ISO strings. The "sort last" behaviour holds only for ascending order. In descending order, series with no next airing come first. The sort functions are exported but only the title sort is tested.
- `shared/src/series.ts (88), server/src/services/series.ts (258)` [minor, 70%]: `addSeriesInputSchema` accepts an optional `title`, but `addSeries` ignores it and always uses `info.title`. `rootFolderPath` is read with the non-null assertion `input.rootFolderPath!`, which is safe only because of a `superRefine` in another file.
- `web/src/pages/series/SeasonSection.tsx; server/src/routes/episode.ts` [minor, 55%]: Toggling a single episode, and "Monitor all" / "Unmonitor all", change episode flags but never update `seasons.monitored`. The test `bulk monitors and leaves season flags alone` locks this in.
- `server/src/routes/series.test.ts` [minor, 75%]: `PUT /series/:id` is tested only for season cascade and 404. Untested paths are: path change (root containment, uniqueness, `rootFolderPath` update), unknown quality profile, unknown tags, and seasons that do not exist. The add-series 503 test checks only the status, not the message.
- `web/src/pages/series/SeriesDetail.tsx` [advisory, 50%]: The detail page loads the whole series list with `useSeriesList()` and finds the series by `titleSlug` on the client. There is no slug-based endpoint.
- `web/src/pages/series/SeriesIndex.tsx` [major, 55%]: After the initial load, a background refetch error is not handled. The `isError` branch only runs when there is no data, and the page shows no inline error for the list or its actions. Separately, the toolbar (view, sort, filter, search) is only rendered in the non-empty branch, and the header's "Add New" action is not rendered in the empty state, so the empty state's own buttons are the only entry points.
- `web/src/pages/series/SeriesIndex.tsx` [minor, 75%]: The table wrapper uses `overflow-hidden`, and the 8-column table has no horizontal scroll (`overflow-x-auto`). The progress column has `min-w-36` and the size column has `whitespace-nowrap`.
- `web/src/pages/series/SeriesIndex.tsx` [minor, 50%]: The sort-direction Button has the static label "Sort direction: ascending/descending" plus a `title`. The sort-key `Select` and the search input are given fixed widths (`w-40`, `w-44`) inside a toolbar that has `min-w-40 flex-1` on the search field.
- `web/src/pages/series/DeleteSeriesModal.tsx` [minor, 50%]: The delete-files warning has `role="alert"`, which is fine. But `onSuccess` calls `onClose()` and `navigate('/')`, and `onClose` is the parent's close, not the local `close`. `deleteFiles` is therefore not reset on success. The checkbox says "Delete series folder" while the intro paragraph says "Files on disk are kept unless you choose to delete them". The wording is inconsistent, and the destructive Delete button has no stronger confirmation than the checkbox.
- `web/src/pages/series/AddNew.tsx` [minor, 50%]: The stretched-link pattern (`after:absolute after:inset-0`) makes the whole card clickable. The "Already in library" badge uses `relative z-10` but has no interactive purpose. While `lookup.isPending` is true for a new term, the previous results stay visible with only `aria-busy` set, and no skeleton is shown. When `trimmed.length < 2`, the debounced term lags the input by 300ms, so stale results can show against a new query.
- `web/src/pages/series/SeriesIndex.tsx` [advisory, 50%]: The table renders missing values as the literal '-' hyphen. Elsewhere in the file the same missing value uses other placeholders. The "Status" and "Seasons" `Th` cells are not sortable, while the toolbar Sort select has other keys.
- `server/src/services/refresh.ts` [minor, 60%]: The comment says a failed refresh must not block the disk scan. When a single-series refresh fails (`ids.length === 1`), `throw e` runs before `app.commands.enqueue('RescanSeries')`, so no rescan is queued. Only the multi-series path reaches the enqueue.
- `server/src/services/series.ts` [major, 70%]: updateSeries accepts a new `path` and updates `series.path` and `rootFolderPath`. It does not enqueue a RescanSeries, and it does not touch the existing `episode_files` rows. Those rows keep their old absolute `path` values and `relativePath`.
- `server/src/routes/episode.ts and server/src/services/series.ts` [major, 65%]: Season `monitored` is stored separately from episode `monitored`. Single-episode toggles and bulk episode monitoring never update the season row. The bulk test explicitly asserts "leaves season flags alone". `updateSeries` skips a season when `cur.monitored === s.monitored`, so the cascade to episodes does not run in that case.
- `server/src/services/diskScan.ts` [minor, 55%]: `addOptions` (the stored add-time monitor option) is consumed only after a scan that reaches the transaction. If the series folder does not exist at the first scan, the function returns early and `addOptions` stays set. The queued add-time scan is also asynchronous, so a user can change monitoring before it runs.
- `server/src/routes/episode.ts` [minor, 50%]: `PUT /episode/:id` publishes the full episode object. `PUT /episode/monitor` publishes `{episodeIds, seriesIds, monitored}`. Disk scan and refresh publish `{seriesId}`.
- `server/src/services/series.ts` [minor, 50%]: `episodeCount` counts only monitored episodes that have a file or have aired. `episodeFileCount` counts every file, including files on unmonitored episodes. `percentOfEpisodes` then divides files by that smaller count and caps it at 100.
- `server/src/routes/rootfolder.ts` [advisory, 55%]: The nesting check uses the shared lexical `isInside` on `path.resolve`d paths. Series and scan containment elsewhere use `realpathLoose` and `realRootFolders` from paths.ts. A symlinked root can therefore pass the nesting check here even though it is nested under another root when resolved.
- `server/src/services/diskScan.ts` [minor, 60%]: The F-005 fix covers `opendir` failures on subdirectories and `stat` failures on files. It does not cover a symlink whose `realpath` or `stat` fails for a transient reason (a network mount, EIO). That path does `continue` without recording anything in `unreadableDirs` or `statFailed`. A symlinked episode file or symlinked season folder that fails transiently is skipped, and the sweep at 293-301 then unlinks its rows.
